# Coast

**一套代理客户端，五个平台，内核自带，装完就能用。**

Windows · macOS · Linux · Android · iOS

[**⬇ 下载最新版本**](https://github.com/ClashrAuto/Coast/releases/latest)

</div>

---

Coast 是一个规则分流代理客户端：订阅节点、按规则分流、看得见每一份流量去了哪里。
内核是本项目自己维护的 [`coast`](https://github.com/ClashrAuto/clash)
（MetaCubeX/mihomo 的 fork），**随安装包一起发出** —— 装完第一次启动就能连，
不用另外下载内核，不用手写 YAML。

除了常规能力之外，它还有三件别的客户端通常没有的事：

1. **桌面端能把整个局域网带上网。** 电视、游戏机、智能音箱这些装不了客户端的设备，
   什么都不用改就能走代理，还能给每台设备单独的策略和时间表。
2. **手机在外面能直连回家里的电脑。** 走自研的 TIDE 协议，经公网 IPv6 点对点，
   不经过任何第三方中转服务器；顺带还能访问家里的内网地址。
3. **可以整个交给 AI 助手管。** 一行命令接上 MCP，之后用说话的方式改规则、换节点；
   但每一处会改变分流的改动都要你在界面上点确认，而且都能撤销。

## 下载

所有安装包都在 [**Releases**](https://github.com/ClashrAuto/Coast/releases/latest)。
文件名的形状是 `Coast-<版本>-<平台>-<架构>[-类型].<扩展名>`。

| 平台 | 选哪个 | 说明 |
|---|---|---|
| **Windows** | `Coast-<ver>-windows-x64-setup.exe` | 装到 `%LOCALAPPDATA%\Coast`，不需要管理员权限 |
| | `Coast-<ver>-windows-x64-portable.zip` | 免安装。解压出来只有 `Coast.exe` + 内核，**没有任何 DLL、没有子目录** |
| | `…-arm64-…` | Surface / 骁龙笔记本等 ARM 设备 |
| **macOS** | `Coast-<ver>-macos-arm64.dmg` | Apple Silicon，需要 **macOS 26** |
| | `Coast-<ver>-macos-universal-qt.dmg` | **兼容版**，最低 macOS 13，Intel 与 Apple Silicon 通用 |
| **Linux** | `Coast-<ver>-linux-x64.deb` | Debian / Ubuntu 系；装到 `/opt/coast`，命令名是 `coast` |
| | `Coast-<ver>-linux-x64-portable.tar.gz` | 免安装 |
| **Android** | `Coast-<ver>-android-arm64-v8a.apk` | 绝大多数手机选这个；另有 `armeabi-v7a` / `x86_64` |
| **iOS** | — | 暂不分发安装包 |

**macOS 那两个包怎么选**：`-qt` 是给跑不了 macOS 26 的机器用的兼容线，功能一致，
界面是 Qt 画的。两条线的更新是各走各的 —— 你装的是哪个，程序就只会给你推哪个。

**Windows 装哪个**：想要开始菜单快捷方式、想用程序内的一键更新，选 `-setup.exe`；
想放 U 盘里、想随时整个删掉，选 `-portable.zip`。

> 包旁边的同名 `.sha256` 文件就是它的摘要（程序内一键更新也用它校验下载完整性），
> 介意的话可以自己核一下。

## 三步开始用

1. **装好打开** —— 内核已经在包里了，不用管「下载内核」那一步。
2. **加订阅** —— 「订阅」页贴上机场给的地址，点更新。
   本地的 `.yaml` 文件、`ss://` / `vmess://` 这类分享链接也认。
3. **打开开关** —— 底部先开「核心」，再按需要开：
   - **网页**（系统代理）：浏览器和大部分桌面程序就够用了
   - **增强**（TUN）：全局接管，不认系统代理的程序也走得通

手机端更简单：加完订阅打开开关，系统会弹一次 VPN 授权。

## 功能

### 订阅与节点

- 远程地址、本地文件都支持；自动识别 **Clash YAML / sing-box JSON / base64 订阅** 三种形态
- 分享链接：`ss` `ssr` `vmess` `vless` `trojan` `hysteria` `hysteria2` `tuic`
- **增量更新**：只动变化的部分，你手动停用过的节点不会被一次更新冲掉
- **定时更新**：每天 / 每周 / 每月，也可以关掉
- **双测速**：延迟（毫秒）和真实下载速度分开测，列表里都看得到；可以只看测得通的
- 单个节点可以单独停用，不用整条订阅一起关
- **允许 / 排除规则**（正则）：把不想要的节点直接滤掉
- **自动地区分组**：`Auto - HK / TW / JP / KR / SG / US / UK / DE`；
  中文名、英文名、三字码（`HKG-01`、`SGP 中转`）都认得出来

### 分流与规则

- 三种模式：**规则** / **全局** / **直连**
- 规则表在设置页里直接改：增、删、改、搜索，还能**单条停用**
  （停用不是删除 —— 规则是首条命中即生效、次序有意义，所以停用的那条留在原位，随时开回来）
- 自己加的规则永远排在内置规则前面
- 一键「初始化规则」恢复出厂，重置前自动备份
- 自定义**区域分组**：用正则把符合条件的节点聚成一组
- GeoIP 库随包发最新的，平时也能在设置里更新

> **内置规则只有 14 条**：局域网/私网直连（12 条，含 IPv6）+ 按 IP 归属地兜底 + 最终兜底。
> 早期版本预置过一千多条按站点分类的规则，后来整体删掉了 —— 那等于替所有用户预设了
> 分流立场，而绝大多数判断「按归属地」一条就够。**出厂也不带任何广告拦截**：
> 拦错东西的表现是「某个网页少一块内容」，用户根本不会想到是代理软件干的。
> 要精细分流，自己加。

### 把局域网设备带上网（桌面端）

让这台电脑成为局域网里其他设备的出口，**被带上网的设备零配置**：不填代理地址、
不改 DNS、不刷路由器。

- 自动发现在线设备，识别厂商，可以改备注名，新设备上线可提醒
- **每设备策略**：跟随全局 / 按规则 / 指定某个节点 / 直连 / **禁网**
- **定时策略**：时间段 + 星期自动切换，比如「小孩的平板每天 22:00–07:00 禁网」，跨零点也算得对
- 每台设备的实时速率和累计用量都看得见
- 电脑插了两条宽带时，每台设备从**它自己连着的那条**出去
- 关掉开关时会主动把被接管设备的 ARP 缓存复原 —— 不会出现「关了开关全家断网」
- 顺带还会告警：**局域网里有别的机器在冒充网关**（ARP 欺骗）时提醒你，
  这类事情平时完全看不见

### 在外面用家里的网

- 桌面端可以开一个公网入口（**默认关闭**），手机在外时直连回来，不经任何第三方服务器
- 走自研的 [TIDE](https://github.com/ClashrAuto/tide) 协议：
  Wi-Fi ↔ 蜂窝切换不断连、UDP 被封自动回落 TCP、认证失败时把流量原样转给掩护站点、
  混合后量子握手
- **配对**：手机扫一下就配上（局域网广播 + 一次性配对码）；桌面之间也能互相扫
- **回家路由**：在外面也能直接访问家里的内网地址（在家 SSH 到 NAS 的 `192.168.31.5`，
  出门再打开还是同一个地址）；回到家自动切回本地直连
- 家宽 IPv6 地址变了会自动推给已配对的设备
- 已授权的设备可以随时查看、随时撤销

### 看得见的用量

- 实时上下行曲线、今日流量、近 30 天流量
- 连接明细：目标、命中了哪条规则、走的哪条代理链、哪个进程、上下行各多少；
  可以按主机过滤，可以断开单条或全部
- **上网历史**（桌面端）：按设备、按域名、按时段统计，存在本地 SQLite 里，保留 30 天
- 日志页：内核日志和程序自己的告警并排显示

### 交给 AI 助手（桌面端）

```bash
claude mcp add coast -- <安装目录>/Coast --mcp
```

接完就能直接说「把 GitHub 走香港那个节点」「今晚 11 点后把客厅电视断网」。

- **默认关闭**，要在「设置 → 允许 AI 助手控制」里手动打开
- 只走本机通道，**不开放任何网络端口**
- 看状态、切节点、断连接这类直接放行；**改规则、改设备策略、开关增强模式
  一律要你在界面卡片上点确认**，不点就不生效，超时按拒绝处理
- 确认卡片说的是**后果**不是方法名 —— 比如「这会让今天 43% 的流量改道，包括 github.com」
- 每条请求都记审计，每处改动都能单独撤销或一键全部撤销

### 手机端

- **按应用分流**（Android）：指定哪些 app 走代理、哪些不走
- 快捷设置磁贴、开机自启（Android）
- **锁屏省电**：锁屏并安静一段时间后自动退回直连，解锁秒级恢复；
  正在听歌、导航、挂下载的时候不会被切
- 轮询按可见性分档、息屏关流 —— 省的是唤醒次数，那才是电池账单上的那一项
- iOS 有锁屏 / 灵动岛的实时活动

### 省心的部分

- 内核随包发布；程序和内核都能在程序里更新，可以选择接收测试版
- 托盘常驻、开机自启、启动到托盘、单实例
- 深浅色跟随系统，也可以强制黑 / 白
- 界面 **13 种语言**：简体中文、繁體中文、English、日本語、한국어、Русский、
  Español、Français、Deutsch、Português、Italiano、Türkçe、Tiếng Việt

## 典型用法

**① 一个人，一堆设备**
电脑、手机、平板各装一份，同一份订阅。五端的配置格式、分组命名、规则语义是逐字对齐的，
不会出现「照电脑写的规则在手机上一条都不命中」。

**② 家里那些装不了客户端的东西**
电视、游戏机、智能音箱、老设备 —— 打开桌面端的「代理网络」，它们什么都不用改。

**③ 家里的网络管理员**
给每台设备单独的策略和时间表；想知道昨晚是谁在下载，翻上网历史；
想知道有没有人在局域网里搞小动作，看告警。

**④ 出差 / 旅行**
手机直连回家里的电脑，用家宽出口；顺手还能连回家里的 NAS。

**⑤ 双宽带**
两条上行各自负责一批设备，互不打架。

**⑥ 自建服务端**
内核自带 TIDE 协议的服务端，在自己的 VPS 上跑一个就行。

## 数据与隐私

**数据放在哪**

| | Windows | macOS | Linux |
|---|---|---|---|
| 数据根 | `%AppData%\Coast\` | `~/Library/Application Support/Coast` | `~/.local/share/Coast` |

下面是 `config/`（配置、订阅、规则）、`logs/`、`command/`（内核）、`Country.mmdb`；
上网历史和设备台账在 `config/coast.db`。**卸载不会动这些文件**，重装后原样还在。

**程序会主动联网的地方，只有这几处**

| 什么时候 | 连哪 |
|---|---|
| 查程序 / 内核有没有新版 | 本仓库的 `version.json`（下面有直链）、GitHub API |
| 下载内核、GeoIP 库 | GitHub Releases |
| 节点测速 | `speed.cloudflare.com` 的下行测试端点 |
| 上网本身 | 你配置里的节点与 DNS，由内核按规则决定 |

**没有任何使用数据上报。** 上网历史、设备台账、连接记录全部只写在本机的 SQLite 里，
不出这台机器；程序里也没有任何统计或崩溃上报的收集端点。

## 常见问题

**装完要不要再下载内核？**
不用。内核在包里，第一次启动会自己落地。设置页里的「更新内核」是给以后升级用的。

**Windows 上开「代理网络」提示要装 Npcap？**
局域网设备代理需要在链路层收发报文，Windows 上这件事要靠 Npcap 驱动。
程序里有引导安装的入口。**只影响这一个功能** —— 系统代理和增强模式都不需要它。

**macOS 第一次打开，为什么问我要不要搬到「应用程序」？**
从 DMG 里直接运行时，macOS 会把程序放进一个随机的只读路径（App Translocation），
那里装不了免密助手，于是增强模式和系统代理都起不来。同意搬一次就好，之后不再问。

**Linux 装 `.deb` 提示缺依赖？**

```bash
sudo apt install -f
```

**手机上为什么没有「设备」页？**
局域网设备代理需要发原始 ARP 报文，非 root 的 Android 拿不到这个权限，iOS 同理。
手机上的对应功能是「按应用分流」（Android）。

**怎么收到测试版？**
设置 → 程序更新 → 打开「接收测试版」。测试版是每个分支每次提交都会出的，更新频繁。

**内核的 API 端口是多少？**
默认 `127.0.0.1:9191`（刻意避开了 9090），可以在设置里改，改完会重启内核。

**能不能直接改 `full.yaml`？**
不建议 —— 它是**生成物**，每次改设置都会重新生成，手改的内容会消失。
规则的真源是 `config/default.yaml` 的 `rules:` 块，设备策略在 `config/coast.db`。

## 这个仓库是什么

**Coast 的发布仓库**：构建流水线（`.github/workflows/`）与所有平台的安装包都在这里。
源码住在另一个仓库（`ClashrAuto/clashauto`），这边的 CI 检出它来构建。

macOS 的两个 DMG 由外部签名仓库签名、公证之后异步追加到同一个 Release 上，
所以一次发布里 macOS 的包可能比别的平台晚到几分钟到几小时。

### 版本清单 `version.json`

客户端查更新不打 GitHub API（未登录的 API 是 60 次/小时/IP，按出口 IP 算 ——
同一个机场出口后面挂几百个用户时谁都查不动，报错还长得像网络故障），
而是读一个固定的清单文件：

```
https://github.com/ClashrAuto/Coast/releases/download/version/version.json
```

它挂在固定 tag `version` 的 Release 上，走资源 CDN，没有限流。结构：

```jsonc
{
  "schema": 1,
  "generated": "…",
  "packages": [ { "type": "release|prerelease", "p": "windows|mac|linux|android",
                  "芯片": "x64|arm64|…", "kind": "setup|portable|deb|dmg|dmg-qt|apk…",
                  "version": "…", "address": "下载直链", "size": 0,
                  "sha256": "同名 .sha256 文件的直链（不是摘要本身）" } ],
  "releases":  { "release": { "tag": "…", "notes": "…" }, "prerelease": { } },
  "core":      { "release": { }, "prerelease": { } },
  "geoip":     { "published": "…" }
}
```

`packages` 是扁平数组，一条 = 一个能下载的包；客户端按「平台 + 架构 + 类型」挑自己那条。
**每次发布只更新本次真正产出的那几条，其余保留上一次的** —— 因为各平台不是同时完成的，
整段覆盖会让用户看到「有新版」却没有包可下。做镜像或者写脚本的话，读它就够了。

### 版本号怎么来的

`大版本.小版本.提交数`，五个平台同一次提交必定是同一个号。
`master` 分支出正式版，其他分支出预发布（程序里打开「接收测试版」才看得见）。
